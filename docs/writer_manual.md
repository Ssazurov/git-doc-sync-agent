# 📖 Руководство технического писателя: Использование Doc-as-Code Copilot

Этот проект представляет собой ИИ-ассистента для автоматического контроля целостности документации проекта на основе синтаксического анализа исходного кода (AST) и файлов документации (в формате упрощенного DocBook XML).

---

## 🛠️ Рабочий процесс технического писателя (Step-by-Step)

Вся документация хранится непосредственно в Git-репозитории проекта по методологии **Doc-as-Code**. Это позволяет исключить рассинхронизацию между разработчиками и документированием.

### 📍 Шаг 1: Получение уведомлений о рассинхронизации
1. Приложение **Doc-as-Code Copilot** запущено в контейнере или локально.
2. В интерфейсе **Streamlit** (или на сервере документации) вы увидите разделы, помеченные красной плашкой `[ ТРЕБУЕТ ПРАВКИ 🔴 ]` или `[ Stale ]`.
3. Под проблемным разделом будет находиться активная ссылка на коммит (например, `[#a1b2c3](https://github.com/Ssazurov/git-doc-sync-agent/commit/a1b2c3)`), в котором разработчик изменил соответствующий программный метод.

### 📍 Шаг 2: Получение ИИ-подсказки и авто-разметка (Вариант Б)
1. Нажмите кнопку **"Создать ветку с разметкой TODO"** под проблемным разделом.
2. ИИ-агент автоматически:
   * Создаст отдельную Git-ветку `docs-sync/fix-[section-id]`.
   * С помощью библиотеки `lxml` вставит специальный маркер-комментарий или черновик правки прямо внутрь XML-файла.
   * Откроет **Pull Request** (PR) в GitHub-репозитории проекта.

### 📍 Шаг 3: Локальная доработка и слияние (Merge)
1. Выполните стягивание изменений в локальный репозиторий:
   ```bash
   git fetch origin
   git checkout docs-sync/fix-[section-id]
   ```
2. Откройте XML-файл в своем любимом редакторе, доработайте текст раздела, опираясь на Todo-разметку от ИИ.
3. Отправьте изменения в репозиторий:
   ```bash
   git add .
   git commit -m "docs: актуализирован раздел по установке"
   git push origin docs-sync/fix-[section-id]
   ```
4. После прохождения ревью Pull Request вливается в ветку `main`. Система автоматически переведет статус раздела в `[ СИНХРОНИЗИРОВАНО ]`.

---

## 📂 Полезные сопутствующие документы в репозитории

Для полного соответствия промышленным стандартам разработки, в корневой папке репозитория `git-doc-sync-agent` рекомендуется разместить следующие файлы:

1. **`CONTRIBUTING.md`** — инструкция для сторонних разработчиков. Описывает правила того, как разработчик при написании нового метода Python обязан добавить соответствующую пустую секцию `<section code_ref="file.py::method">` в XML, чтобы не ломать сборку.
2. **`architecture_design.md`** — детальное системное описание взаимодействия агентов в LangGraph (AST-Detective ➔ XML-Navigator ➔ PR-Coordinator) с использованием картинок.
3. **`github_workflow_actions.yml`** — конфигурация CI/CD пайплайна для GitHub Actions. При каждом коммите в `main` пайплайн автоматически запускает `detector.py`, проверяет целостность и при наличии расхождений создает автоматическую задачу в GitHub Issues.
